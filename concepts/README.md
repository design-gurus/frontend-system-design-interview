# Concepts

These ten pages cover the topics that a frontend system design interviewer is most likely to probe. Each page gives the definitions, one decision table, and the statement to make in the round.

| Page | Read it when the question involves |
|---|---|
| [Rendering strategies](rendering-strategies.md) | First load speed, search indexing, or personalized pages |
| [State management](state-management.md) | Data shared across components or screens |
| [Data fetching and caching](data-fetching-and-caching.md) | Lists, pagination, or stale data |
| [Performance and Core Web Vitals](performance-and-core-web-vitals.md) | Any quality target stated in milliseconds |
| [Real-time updates](real-time-updates.md) | Chat, notifications, or live numbers |
| [Offline and storage](offline-and-storage.md) | Unreliable networks or drafts that must survive a reload |
| [Accessibility](accessibility.md) | Any interactive component |
| [Security](security.md) | User-generated content or sign-in |
| [Component API design](component-api-design.md) | Component questions such as autocomplete or a data table |
| [Micro-frontends](micro-frontends.md) | Many teams working on one product |

The method that ties these topics together is in [the framework](../framework.md).
